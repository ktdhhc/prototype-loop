# 逐题对齐

> 阶段 5 每层在渲染验收与初选后使用。先按主文件的“实际加载契约”确认 `grilling` 原指令可用，再执行决策核对；原指令不可用时按该契约重新加载，失败则停止。本节是本流程的挂靠约束，不是 `grilling` 的替代指令。一次一问、等待回答、自己核对可查的事实；核对完成后请用户确认共同理解。初选不代替本环节。

## 核心原则：只问决定性问题

用户原话（约束本节一切规则）：

> 不要每层都固定保持完全一样的问题类型序列……灵活思考，只问最有决定性作用的问题。

**决定性 = 答案会改变后续做法。** 操作化为"挂靠"机制：

1. 每层初选后，先结合界面简述、渲染反馈与所选方案，在账本列出**本层的不确定点清单**。核对会改变做法的取舍、所接受的代价和适用边界，既看已暴露的分歧，也检查尚未被讨论的决策；这不是固定题序，不把未来层的问题搬进来。
2. 每个问题必须挂在一个不确定点上；挂不上的不问。已有明确回答的点注明依据，可查事实自行核对，真正延后到其他层的事项写明归属。
3. 沿会改变本层做法的决策分支逐题核对，回答引出新的未定点时继续；有意延后的事项写明去向，不把未决包装成共识。
4. 核对完成后，展示本层结论、关键理由与代价、延后事项，请用户确认共同理解；之后回到层循环固化基线、清理与验证，通过收层闸门才冻结。

反例对照：某轮按固定序列问"落选补偿""边界条件"，用户答"都不搬 / 都不算例外"——两问零信息，还被批评"不痛不痒"。而同轮的"左栏要不要同档密度"一问改变了两栏的整个密度策略，是真问题。差别不在题型，在**挂没挂上不确定点**。

## 核对必做，允许零提问

零提问是执行 grilling 核对后的结果，不是略过核对的路径。只有本层会改变做法的决策均已有明确答案、可查事实已核对、延后事项有去向时，才无须制造额外问题。

账本写出核对了哪些本层决定、答案来自何处、哪些事项不属本层；“用户已选 B”“用户没提问题”或单写“本层无额外问题”都不是充分依据。例如：

> 本层仅决定导航位置；选择理由与窄屏行为已在访谈及渲染验收中确认。密度归属 L3。本层没有新增未定决策，零额外提问。

无论是否零提问，都展示本层结论并获得用户确认；已有回答不重复追问，但原型初选或推进授权不能自动填作结论确认。

## 一次一问

- 用 AskUserQuestion 提问，一次只问一个，等回答再问下一个。
- 每问带**推荐答案**（放选项第一位并标注），推荐来自已冻结的层与设计纪律的推演。
- 用户关闭问题面板 = 该问不成立，转为纯文本列出待定点，不编造用户偏好。
- 事实类信息（仓库里有、领域文档里有）自查，不问用户；只问**决定**。

## 题型库（措辞参考，不是流程）

| 题型 | 适用时机 | 示例 |
| --- | --- | --- |
| 取舍 | 2–4 个结构选项并存 | "三档密度倾向哪个？" |
| 理由 | 取舍之后（决定后续冲突偏向） | "选它的最主要理由是哪个？" |
| 落选补偿 | 落选项里有局部值得吸收 | "落选的 A/C 里有什么想搬进来的？" |
| 边界 | 该层的例外情形 | "哪些情况会推翻这个选择？" |
| 待完善 | grilling 核对末尾、确认结论前的开放式 | "最不满意 / 最想调整的是哪些？" |
| 跨层归属 | 用户提出新输入时 | （不问用户，agent 自行归类并报告） |

使用规则：按不确定点**取用**，不按顺序**套用**；同一层可以只用其中一两种，也可以全部不用。

## 问题设计的三个技法

1. **选项写"决策 + 代价"**：每个选项不只说它是什么，还说它的代价——用户在知情下选择（"D2：行干净，但次要动作多一次点击"）。
2. **预览用文本骨架**：选项可带 ASCII 骨架图表达结构差异（prototype 技能的变体精神在提问里的延伸）；先做原型再看的不需要预览。
3. **混合偏好是拆层信号**：用户若想要“A 的骨架 + B 的密度”，分别记录两种偏好；把密度移到对应层处理，并重做被污染的骨架变体。只有同一决策点内可兼容的局部取舍，才在本层合并。

## 推翻与反复

用户推翻先前答案（含中途推翻自己刚选的）= 正常事件。处理：立即回退受影响产物、账本记"原结论 → 推翻原因（尽量引原话）→ 新结论"，然后继续本层流程。不质疑、不挽留、不在后续问题里暗示"你之前选过另一个"。

## 收层

用户确认本层原型与决定后进入“待收层”：账本写核对依据、问答与定稿描述，标 `ΔDESIGN`（如适用），再按 [层循环](prototype-loop.md) 第 5–6 步固化基线、清理和验证；通过收层闸门才冻结并停层。下一层授权或连续推进授权只控制冻结后的推进，不代替上述环节。

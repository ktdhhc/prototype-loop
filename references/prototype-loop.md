# 层循环（Layer Loop）

> 阶段 5 执行。每层四拍：锁轴原型 → 渲染验收 → grilling → 冻结停层。外部依赖：prototype 技能（变体切换、悬浮条规范）、AskUserQuestion 工具（grilling 载体）。

## 第 1 拍 — 锁轴原型

本层只变本层那一轴；其余轴全部锁死为已冻结的定稿（上游层）或空位占位（下游层）。

**规则**

- **锁轴是前提不是优化**。历史教训：变体 B（紧凑两栏）与变体 C（舒展抽屉）同时差拓扑和密度，用户的选择被污染（"倾向 B 又舍不得 C 的密度"），整轮返工。开建前先写下"本层变体之间唯一的差异是什么"，写不出就回拆层。
- **空位占位块**：未决定的内容用统一的占位组件，让用户看到预留范围而不引入具体做法；归属层只记在账本，不把内部流程标签渲染为产品内容。
- **占位分两种，视觉可区分**：本层未定的脚手架（收口删除）与"无真实接口"的诚实占位（长期保留，用标注青 + 可见文字）。
- **真实链路优先**：功能原型尽量复用项目已有命令与可运行数据，尤其是运行进度、阻断和取消；需要合成状态时明确标为只读演示样本。组件库采样只比较视觉，可用静态示例。
- **变体切换**：按已加载 `prototype` 技能的当前 UI 变体约定制作可切换原型。一次只比较本层决策点；切换控件是临时工具，收口时清理。
- **样本态**：当真实数据难以同时呈现多种状态（空 / 加载 / 失败 / 阻断 / 取消残留 / 超长）时，建一份**只读演示样本**（不写库、页内标注"状态样本"），让用户不用真跑就能对照各状态。历史教训：内存 mock 刷新即空，用户打开页面全是空白，"完全没有办法选择"。
- **从第一拍遵守当前项目的视觉纪律**：用已选组件库的推荐组件、尺寸与间距；检查容器内文字留白、既有字阶及图标按钮的可访问名称。案例集页曾因忽略这些约束而反复返工；其他项目按各自视觉依据判断。

## 第 2 拍 — 渲染验收

原型可点后交用户在真实浏览器里看（生产构建照常可用的前提下，dev 环境走查）。用户的每条反馈三分归类：

| 反馈类型 | 处理 |
| --- | --- |
| 违反当前项目既有设计约束或出现可见实现错误 | **当场修**——这不是本层的新设计决策 |
| 本层未定的决策点 | 进 grilling 问题池 |
| 属于别的层的输入 | 记跨层待办，不当场做（"进度卡展开进会话"在骨架层提出 → 记到动作层） |

渲染验收是信息量最大的环节——大部分关键修正（对齐、重复、密度、信息命名）来自用户看真实页面，而非脑内推演。宁可多轮验收，不替用户想象。

## 第 3 拍 — grilling

按 references/questions.md 执行。要点预览：一次一问、只问挂在"本层不确定点"上的决定性问题、每问带推荐答案、用户推翻属正常事件。

## 第 4 拍 — 冻结 + 停层

1. 用户确认本层原型与结论后，在账本记录逐问结果及定稿描述；有未决项则标明去向。
2. 涉及视觉权威的决策标 `ΔDESIGN`（供收口回写 DESIGN.md）。
3. 向用户输出：**本层定稿摘要 + 下一层预告（做什么、为什么现在做、预计几拍）**。
4. **停下。** 用户说"继续 / 下一层"才动。层与层之间是用户驱动的状态机：冻结后输出预告，把推进权交还用户，每层都在用户的放行下开始。
   - 例外：用户显式授权连续推进（"后面几层连着做"）→ 账本记一笔，按授权范围连续执行，出授权范围即停。
   - 用户在停层期插入新输入 → 先归类：属于已定稿层 → 回退重开该层（见下）；属于未来层 → 记跨层待办。

## 回退协议

用户推翻某个已冻结的决策，或在渲染验收中暴露结构理解错误：

1. **回到该层决策前**，找出仅为错误方案服务的变体、附属原型和样本。核对所有权与工作区状态后清理；对存在用户或并行改动的文件先停下确认，不在错误结构上叠补丁。
2. 账本记录：推翻原因、用户原话要点、新方向。
3. 重做该层原型，重新走四拍。
4. 下游层若已建立在被推翻的结论上 → 一并标记回退，按闸门流程重新确认分层表（通常无需重拆层，只需重做受影响的层）。

推翻是正常事件：在账本保留决策变化的原因，交付说明只保留当前结论与仍未解决的边界。

# 拆层：从轴到层

> 阶段 4 使用。输入：界面简述、检索结论、静态参考轴池；产出：经用户认可的分层表和每层的变体证明，均记录在本项目过程账本中。
>
> 拆层是本流程唯一"错了就全盘返工"的环节，所以它被设计成**两步文档化预演 + 用户闸门**，而不是一次成型的判断。

## 三步协议

### 第 1 步 — 枚举轴（全集，先不管顺序与层数）

三个来源逐一过，宁多勿漏（多出来的轴在独立性判定时自然合并）：

- **轴池**（references/axis-pool.md）：逐条问"本界面有这个轴吗"。
- **界面简述映射**：逐条核对素材、行为与边界——数据范围可能涉及信息类型和密度，状态清单可能涉及状态与边界；“不能动什么”进入约束区。
- **用户概念归类**：用户提出的每个概念（"批次进度""进入会话"）先归类到某个轴，而不是直接当层。

### 第 2 步 — 独立性判定（裂解大轴）

对每个候选轴问："它能否在保持其他轴不变的情况下独立变化？"

- 能 → 独立轴。
- 不能 → 并入它依附的轴，或与其他轴合并。
- 顺带记录依赖关系："改这层要重做哪些层"——被依赖越多，影响半径越大。

### 第 3 步 — 分配 + 排序 + 自检

1. 按影响半径排序：**被依赖多者在前**。排序判据可测：改这层的决策，需要重做哪些层？骨架改了几乎重做一切 → 最前；状态边界改了几乎不影响他层 → 最后。轴池的排列是管理台类的经验序，**当前界面的序以依赖关系为准**。
2. 依赖环（A 依赖 B、B 依赖 A）= 拆错的信号 → 回第 2 步把环里的轴合并或重新裂解。
3. 把轴分配为层。需要合并或裂解时，先写明这一层实际要回答的**唯一问题**；只有各变体可保持其他设计维度不变，才算同一层。

## 两步预演（强制，落在账本里）

预演不是脑内自检——它是账本里的可见产物，闸门时用户看到的是"初版 + 证明"，多轴的层在纸面上无处藏身。

**步骤 A — 写分层表初版**进过程账本，每层三栏：

```markdown
| 层 | 唯一决策点 | 明确不决定 |
| --- | --- | --- |
| 骨架布局 | 页面切成几块、各块在哪 | 每块放哪些字段、动作怎么排 |
```

**步骤 B — 反事实测试**，对每层构造 2–3 个**只差一件事**的变体描述，结果写回账本：

```markdown
| 层 | 变体证明 |
| --- | --- |
| 骨架布局 | ✅ 目录+详情二级路由 / 单页两栏 / 单页+抽屉（三者只差拓扑） |
| 信息密度 | ✅ 极紧一行 / 分列两行 / 舒展层级（三者只差密度，字段相同） |
```

写不出只差本层决策点的变体，说明该层可能混入了另一个轴：回到独立性判定，重拆并重测。

**变体之间只差本层的关键维度**：若本层比较骨架，改颜色不足以证明骨架方案不同；若本层正比较颜色，颜色就是有效差异。把变体并排看，用户若说“倾向 A 的骨架，又舍不得 B 的密度”，说明比较混入了另一个轴，需锁住密度重画。

## 层数上限

初版层数 > 12：停下来向用户报告，并给出切分建议——

- **拆成两个页面**（各 ≤12 层，各自完整走层循环与收口），或
- **同一页面分两大轮**（轮之间也有闸门确认）。

给切分建议的依据是依赖序的天然断层（影响半径排序后，找到"后半层不依赖前半层全部"的断点）。层数超标是"一个界面承载了两个界面"的信号；切不切、怎么切由用户决定，agent 不自动执行。

## 闸门

把账本里的**初版 + 变体证明 + （如适用）拆分建议**一并交给用户，判"这次对了"才进入层循环。闸门被否 = 用户主权的正常行使：按反馈修改初版、重跑受影响的变体测试，再次过闸。协议服务于判断，不替代判断——用户认可的分层就是对的，agent 的职责是把证明摆全。

## 反例库（拆层踩过的坑）

| 反例 | 症状 | 修法 |
| --- | --- | --- |
| 两个轴挤一层 | 用户判"第一层包含的可决策内容太多了" | 先枚举轴全集再分配——层名从轴的分配中产生 |
| 轴缺失 | 初版漏掉信息密度或组件样式 | 逐条核对静态轴示例与界面简述，不靠自由发挥 |
| 变体污染 | "倾向 B 但更倾向 C 的密度"——选择跨轴 | 锁轴：变体之间只许差一件事 |
| 私自连做 | 上一层冻结后顺手画了下一层的东西 | 层间强制停（references/prototype-loop.md） |
| 错误结构上打补丁 | 在误解的 A 档上叠子原型与样本，被整体否决 | 回退到该层定稿前重做，删干净落选产物 |
